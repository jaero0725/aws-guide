SQS + Lambda 비동기 처리

큐를 넣는 이유는 유입 속도와 처리 속도를 분리하기 위해서입니다. 처리가 늦어도 요청이 유실되지 않고, 처리 계층은 자기 속도로 소비합니다. 이 실습에서는 큐와 배달 못한 편지 큐(DLQ)를 만들고, 실패를 일부러 만들어 메시지가 어디로 가는지 확인합니다.

관련 도메인: 복원력 있는 아키텍처 설계(26%)

학습 목표

  • 표준 큐와 FIFO 큐의 차이를 알고 상황에 맞게 고를 수 있습니다.
  • 가시성 제한 시간과 함수 제한 시간의 관계를 설명할 수 있습니다.
  • 재구동 정책으로 DLQ를 구성하고 넘어가는 조건을 정할 수 있습니다.
  • 이벤트 소스 매핑의 배치 크기와 대기 시간이 무엇을 바꾸는지 이해할 수 있습니다.
  • 중복 전달에 대비한 멱등 처리의 필요성을 설명할 수 있습니다.

시나리오

주문이 들어오면 영수증을 만들고 알림을 보내는 후처리를 합니다. 후처리는 몇 초가 걸리고 가끔 외부 서비스 오류로 실패합니다.

  • 주문 접수는 즉시 응답해야 하므로 후처리를 동기로 두지 않습니다.
  • 후처리가 실패해도 메시지가 유실되면 안 됩니다.
  • 계속 실패하는 메시지가 큐를 막지 않아야 합니다.
  • 순서 보장은 필요하지 않습니다.

마지막 조건 때문에 표준 큐를 고릅니다. 순서와 중복 제거가 필요했다면 FIFO 큐를 골라야 하고, 처리량 특성이 달라집니다.

구성 단계

1 · 큐와 DLQ 만들기

DLQ의 보존 기간은 주 큐보다 길게 잡습니다. 실패한 메시지를 조사할 시간이 필요한데, DLQ의 보존 기간이 짧으면 원인을 찾기 전에 사라집니다.

2 · 처리 함수

배치 안의 한 건이 실패했을 때 배치 전체를 다시 처리하면 이미 성공한 건까지 중복 처리됩니다. 위처럼 실패한 항목만 보고하면 성공한 건은 큐에서 제거됩니다. 이 동작을 쓰려면 이벤트 소스 매핑에서 부분 배치 응답을 켜야 합니다.

실행 역할에는 로그 권한과 함께 sqs:ReceiveMessage, sqs:DeleteMessage, sqs:GetQueueAttributes 권한이 필요합니다. 이벤트 소스 매핑에서 Lambda 서비스가 함수의 역할로 큐를 폴링하기 때문입니다.

3 · 이벤트 소스 매핑

가시성 제한 시간은 함수 제한 시간보다 길어야 합니다. 함수가 아직 처리 중인데 가시성 제한 시간이 끝나면 같은 메시지가 다른 실행에 다시 전달되어 중복 처리가 일어납니다.

배치를 쓴다면 여유가 더 필요합니다. 배치 크기만큼의 처리 시간과 재시도를 함께 고려해 값을 정합니다. 이 실습에서는 함수 제한 시간 30초에 가시성 제한 시간 180초로 여유를 뒀습니다.

비용과 지연은 배치 크기와 대기 시간에서 맞바꿉니다. 배치를 키우고 대기 시간을 늘리면 호출 수가 줄지만 처리 지연이 커집니다. 지연 요구를 먼저 정하고 그 범위 안에서 배치를 키우는 순서가 맞습니다.

프로덕션 고려사항

  • 처리를 멱등하게 만듭니다. 표준 큐는 중복 전달이 발생할 수 있으므로, 같은 메시지를 두 번 처리해도 결과가 같아야 합니다. 처리 완료를 기록하는 테이블을 두는 방식이 흔합니다.
  • DLQ를 감시합니다. DLQ에 메시지가 쌓이는 것은 장애 신호입니다. 메시지 수에 알람을 걸어 둡니다(실습 12).
  • 큐 적체를 기준으로 확장합니다. Lambda는 자동으로 확장하지만, 소비자가 컨테이너나 인스턴스라면 대기 메시지 수를 지표로 삼습니다.
  • 동시성을 제한합니다. 하류 데이터베이스가 감당할 수 있는 수준으로 예약 동시성을 두지 않으면 큐가 완충한 부하가 그대로 데이터베이스로 전달됩니다.
  • 메시지 크기 상한을 넘길 데이터는 Amazon S3에 두고 키만 보냅니다.
  • 암호화와 접근 제어. 큐에 저장 데이터 암호화를 켜고, 큐 정책으로 송신자와 수신자를 한정합니다.
  • 순서가 필요해지면 큐를 새로 만들어야 합니다. 표준 큐를 FIFO로 바꿀 수 없습니다.

정리 — 리소스 삭제

큐를 삭제한 뒤 같은 이름으로 다시 만들려면 최소 60초를 기다려야 합니다. 실습을 반복할 때 이름을 재사용하다가 오류를 만나면 이 제약 때문입니다.

공식 문서 출처

  • Amazon SQS API 레퍼런스 — CreateQueue — 표준 큐가 기본이고 유형을 바꿀 수 없다는 서술, 큐 속성의 범위와 기본값, 삭제 후 같은 이름 재생성에 60초가 필요하다는 제약
  • Amazon SQS API 레퍼런스 — ChangeMessageVisibility — 가시성 제한 시간의 기본 30초, 최소 0초, 최대 12시간
  • Amazon SQS API 레퍼런스 — SendMessage — FIFO 큐에서 MessageGroupId가 없으면 실패한다는 동작
  • Amazon SQS 개발자 안내서 — 고처리량 FIFO — FIFO의 초당 300개, 배치 사용 시 3,000개 기준
  • AWS Lambda API 레퍼런스 — CreateEventSourceMapping — 배치 크기, 배치 대기 시간, 함수 응답 유형 설정
  • Amazon SQS API 레퍼런스 — StartMessageMoveTask — DLQ의 메시지를 원래 큐로 되돌리는 작업
