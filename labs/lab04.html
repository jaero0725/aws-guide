RDS Multi-AZ와 읽기 전용 복제본

시험이 가장 집요하게 노리는 쌍을 손으로 확인하는 실습입니다. 같은 데이터베이스에 Multi-AZ와 읽기 전용 복제본을 함께 구성하고, 장애 조치를 직접 일으켜 엔드포인트가 어떻게 움직이는지 봅니다. 표로 외우는 것과 실제로 보는 것은 다릅니다.

관련 도메인: 복원력 있는 아키텍처 설계(26%) · 고성능 아키텍처 설계(24%)

학습 목표

  • 프라이빗 서브넷만으로 DB 서브넷 그룹을 만들어 데이터베이스를 배치할 수 있습니다.
  • Multi-AZ를 켜고 강제 장애 조치를 일으켜 엔드포인트 유지 여부를 확인할 수 있습니다.
  • 읽기 전용 복제본을 만들고 별도 엔드포인트가 생기는 것을 확인할 수 있습니다.
  • 복제본 승격이 자동이 아니라는 사실을 실행으로 확인할 수 있습니다.
  • 실습 후 스냅샷 처리까지 포함해 리소스를 정리할 수 있습니다.

시나리오

실습 1의 데이터베이스 서브넷에 관계형 데이터베이스를 만듭니다. 확인할 것은 둘입니다.

  • Multi-AZ 장애 조치가 일어나면 애플리케이션이 쓰는 엔드포인트 주소가 바뀌는가.
  • 읽기 전용 복제본은 어떤 주소로 접근하고, 프라이머리가 죽으면 어떻게 되는가.

배경 개념은 10장 RDS와 관계형 데이터베이스에 있고, 어느 처방이 어떤 문제를 푸는지는 케이스 2 · 읽기 부하로 데이터베이스가 죽었다에서 다룹니다.

읽기 전용 복제본 개수에는 상한이 있습니다. MySQL · MariaDB · PostgreSQL은 인스턴스당 최대 15개, Oracle과 SQL Server는 5개, Db2는 3개입니다.

구성 단계

1 · DB 서브넷 그룹

서로 다른 가용 영역의 프라이빗 서브넷만 넣습니다. 퍼블릭 서브넷을 넣으면 나중에 퍼블릭 액세스 설정 실수가 곧바로 노출로 이어집니다.

2 · Multi-AZ 데이터베이스 만들기

--manage-master-user-password를 쓰면 마스터 비밀번호를 AWS Secrets Manager가 관리하고 교체까지 처리합니다. 비밀번호를 명령줄에 직접 적으면 셸 기록에 남으므로 피합니다.

--storage-encrypted는 생성 시점에만 지정할 수 있습니다. 암호화되지 않은 인스턴스를 나중에 암호화하려면 스냅샷을 만들어 암호화 옵션으로 복사한 뒤 복원해야 합니다.

3 · 읽기 전용 복제본 만들기

원본 인스턴스는 자동 백업이 활성화되어 있어야 복제본을 만들 수 있습니다. 위에서 --backup-retention-period 7을 준 이유가 이것입니다. 만들어진 복제본은 백업이 비활성화된 상태로 생성됩니다.

검증 방법

엔드포인트 비교

여기서 확인할 것은 셋입니다. 프라이머리에 보조 가용 영역이 채워져 있고, 복제본은 다른 엔드포인트 주소를 가지며, 복제본에는 원본 식별자가 표시된다는 점입니다.

강제 장애 조치

장애 조치 전후에 무엇이 바뀌고 무엇이 그대로인가
항목 결과 의미
엔드포인트 주소 그대로 애플리케이션 설정을 고칠 필요가 없다. DNS가 새 인스턴스를 가리킨다
가용 영역 바뀐다 대기 인스턴스가 있던 가용 영역으로 이동했다
연결 일시적으로 끊긴다 애플리케이션에 재연결 로직이 필요하다
복제본 엔드포인트 그대로 복제본은 장애 조치와 무관하게 자기 주소를 유지한다

엔드포인트 주소가 유지된다고 연결이 유지되는 것은 아닙니다. 기존 연결은 끊기고 재연결이 필요합니다. 그리고 클라이언트나 JVM 같은 런타임이 DNS 결과를 오래 캐시하면 전환 후에도 옛 주소로 접속을 시도합니다. DNS 캐시 시간을 짧게 두는 것이 장애 조치 시간을 실제로 줄입니다.

복제본은 자동 승격되지 않는다

읽기 전용 복제본이 재해 복구 수단이 되려면 승격이 필요하고, 이 작업은 자동으로 일어나지 않습니다. 승격하면 복제 관계가 끊기고 독립 인스턴스가 됩니다.

비용 판단의 요점은 무엇을 사는가입니다. Multi-AZ는 가용성을 사고, 복제본은 읽기 처리량을 삽니다. 읽기가 문제인데 Multi-AZ를 켜면 비용만 늘고 문제는 남습니다.

프로덕션 고려사항

  • 애플리케이션에 재연결과 재시도. 장애 조치는 짧은 중단을 동반합니다.
  • 읽기 경로를 분리하되 전부 보내지 않습니다. 복제 지연을 허용할 수 없는 쿼리는 프라이머리로 고정합니다.
  • 복제 지연을 지표로 감시합니다. 지연이 커지면 읽기 경로를 되돌릴 수 있어야 합니다.
  • 연결 수가 병목이면 RDS Proxy. 서버리스 워크로드에서 연결 고갈은 인스턴스 크기로 풀리지 않습니다.
  • 암호화는 생성 시점에. 나중에 켜려면 스냅샷 복사 경로가 필요합니다.
  • 매개변수 그룹과 유지 관리 창을 명시적으로 관리합니다. 기본 매개변수 그룹은 수정할 수 없습니다.
  • 삭제 보호를 켜 두면 실수로 인스턴스를 지우는 사고를 막습니다.

정리 — 리소스 삭제

삭제할 때 최종 스냅샷을 만들면 인스턴스를 지운 뒤에도 스냅샷 요금이 남습니다. 실습 리소스라면 최종 스냅샷을 만들지 않도록 명시합니다. 반대로 운영 환경에서는 최종 스냅샷 생략이 위험합니다.
