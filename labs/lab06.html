Lambda + API Gateway REST API

서버리스 HTTP 엔드포인트를 만듭니다. 이 실습에서 반드시 이해하고 넘어갈 것은 권한이 두 방향이라는 점입니다 — 함수가 다른 서비스를 호출할 때 쓰는 실행 역할과, API Gateway가 함수를 호출하도록 허용하는 리소스 기반 권한은 서로 다릅니다.

관련 도메인: 복원력 있는 아키텍처 설계(26%) · 보안 아키텍처 설계(30%)

학습 목표

  • Lambda 실행 역할과 리소스 기반 권한의 역할 차이를 설명할 수 있습니다.
  • API Gateway REST API에 프록시 통합으로 함수를 연결할 수 있습니다.
  • 스테이지 배포 개념과 변경이 반영되는 시점을 이해할 수 있습니다.
  • 제한 시간·메모리·동시성 설정이 무엇을 바꾸는지 설명할 수 있습니다.
  • 콜드 스타트가 생기는 조건과 완화 수단을 구분할 수 있습니다.

시나리오

내부 도구용 조회 API를 만듭니다. 트래픽은 평소 거의 없다가 특정 시간에만 몰리고, 서버를 상시 띄워 두고 싶지 않습니다. 이런 형태가 서버리스가 가장 잘 맞는 조건입니다.

  • GET /items로 항목 목록을 반환합니다.
  • 인증은 이 실습 범위 밖으로 두고, 나중에 붙일 자리만 확인합니다.
  • 배포는 스테이지로 구분합니다.

권한의 두 방향을 구분하는 것은 시험에서도 반복됩니다.

  • 함수가 무엇을 할 수 있는가 → 실행 역할(자격 증명 기반 정책)
  • 누가 함수를 호출할 수 있는가 → 함수의 리소스 기반 정책

Amazon ECS에도 같은 구분이 있습니다 — 태스크 역할과 태스크 실행 역할입니다 (실습 9).

구성 단계

1 · 실행 역할

2 · 함수 만들기

런타임 이름은 시간이 지나면 지원이 끝납니다. 위 값을 그대로 쓰기 전에 aws lambda list-runtimes 또는 지원 종료 일정 문서를 확인하고, 현재 지원되는 버전을 씁니다.

제한 시간의 기본값은 3초이고 최대는 900초(15분)입니다. 메모리는 기본 128 MB, 최대 10,240 MB이며 메모리를 늘리면 CPU 할당도 함께 늘어납니다. CPU가 부족해 느린 함수는 메모리를 올려 해결되는 경우가 많습니다.

3 · REST API 만들기

--integration-http-method는 항상 POST입니다. 클라이언트가 GET을 보내더라도 API Gateway가 Lambda를 호출할 때 쓰는 메서드는 POST입니다. 여기를 GET으로 적으면 호출이 실패합니다.

4 · 호출 권한 부여

여기까지 만들어도 호출하면 실패합니다. 함수 쪽에 "이 API가 호출해도 된다"는 권한을 기록해야 합니다.

--source-arn을 생략하면 모든 API Gateway가 이 함수를 호출할 수 있게 됩니다. 특정 API와 경로로 좁히는 것이 최소 권한 원칙에 맞습니다.

5 · 스테이지 배포

REST API는 배포해야 변경이 반영됩니다. 메서드나 통합을 고쳐도 새 배포를 만들지 않으면 스테이지에는 옛 구성이 남습니다. "고쳤는데 그대로다"의 대부분이 이 원인입니다.

프로덕션 고려사항

  • 인증을 붙입니다. IAM 인증, Lambda 권한 부여자, Amazon Cognito 등 요구에 맞는 방식을 고릅니다. authorization-type NONE을 그대로 두지 않습니다.
  • 사용량 계획과 API 키로 클라이언트별 속도를 제한할 수 있습니다.
  • 동시성을 관리합니다. 예약 동시성으로 한 함수가 계정 전체 동시성을 잠식하지 않게 막고, 지연에 민감한 함수에는 프로비저닝된 동시성으로 콜드 스타트를 줄입니다.
  • 로그 보존 기간을 명시적으로 설정합니다.
  • VPC 연결은 필요할 때만. VPC에 연결하면 인터넷이나 퍼블릭 AWS 엔드포인트로 나가기 위해 NAT 게이트웨이나 VPC 엔드포인트가 필요해집니다.
  • 배포는 별칭과 버전으로. 별칭에 가중치를 주면 점진적 전환이 가능합니다.
  • 동기 호출 페이로드 상한은 6 MB입니다. 큰 데이터를 주고받아야 하면 Amazon S3에 두고 키만 전달합니다.

정리 — 리소스 삭제

로그 그룹은 함수를 지워도 남습니다. 보존 기간을 설정하지 않았다면 계속 쌓이므로 함께 정리합니다.

공식 문서 출처

  • AWS Lambda API 레퍼런스 — CreateFunction — 제한 시간 기본 3초·최대 900초, 메모리 기본 128 MB와 CPU 동반 증가, 런타임 값

  • Amazon API Gateway API 레퍼런스 — PutIntegration — 통합 유형(AWS_PROXY 등)과 통합 HTTP 메서드
  • Amazon API Gateway API 레퍼런스 — CreateDeployment — 스테이지 배포가 있어야 변경이 반영된다는 동작
