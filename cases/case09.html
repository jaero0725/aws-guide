온프레미스 파일 서버를 클라우드로

파일 서버 마이그레이션은 서비스 이름을 외워서 푸는 문제가 아닙니다. 어떤 프로토콜로 · 누가 · 어디에서 접근하는가, 그리고 온프레미스를 남길 것인가 없앨 것인가를 물으면 Storage Gateway · Amazon FSx · AWS DataSync 중 하나로 자연스럽게 수렴합니다.

주 도메인: 고성능 아키텍처 설계(24%) · 비용 최적화 아키텍처 설계(20%)

학습 목표

  • 공유 스토리지 후보를 프로토콜과 접근 주체 기준으로 좁힐 수 있습니다.
  • Storage Gateway의 유형별 경계(온프레미스에 무엇이 남는가)를 설명할 수 있습니다.
  • 이관 도구(DataSync)와 상시 연결(Storage Gateway)의 역할 차이를 구분할 수 있습니다.
  • 전송량과 가용 대역폭으로 소요 기간을 추정하고 전송 수단을 판단할 수 있습니다.
  • 시험 문항에서 "기존 인프라를 유지"와 "완전히 이전"의 신호를 구분할 수 있습니다.

상황

제조업체의 본사 데이터센터에 Windows 파일 서버 두 대가 있습니다.

  • 설계 부서가 SMB 프로토콜로 도면 파일을 공유합니다. 권한은 Active Directory 그룹으로 관리됩니다.
  • 총 용량은 수십 테라바이트이고, 그중 최근 3개월 파일만 실제로 자주 열립니다.
  • 본사 회선의 여유 대역폭은 크지 않고, 업무 시간에는 더 좁습니다.
  • 공장 라인의 검사 장비가 파일 서버에 결과를 쓰는데, 이 장비는 소프트웨어를 수정할 수 없습니다.
  • 분석 팀은 이 파일들을 AWS에서 처리하고 싶어 합니다.

요구는 상충합니다. 분석을 위해 데이터는 클라우드에 있어야 하지만, 공장 장비와 설계 부서는 지금과 똑같은 SMB 경로로 계속 접근해야 합니다. 그리고 회선이 좁아 한 번에 다 올릴 수도 없습니다.

후보 설계안 비교

먼저 세 서비스의 역할이 다르다는 점을 정리합니다. DataSync는 옮기는 도구이고, Storage Gateway는 이어 주는 장치이며, FSx는 클라우드 쪽의 파일 서버 자체입니다. 셋은 경쟁 관계라기보다 조합해 쓰는 경우가 많습니다.

FSx File Gateway는 신규 고객에게 더 이상 제공되지 않습니다. 기존 고객은 계속 사용할 수 있습니다. 따라서 새로 설계할 때 온프레미스에서 FSx로의 접근이 필요하다면 게이트웨이가 아닌 다른 연결 수단(전용 회선이나 VPN을 통한 직접 접근)을 검토합니다. 게이트웨이 유형을 외울 때는 S3 File Gateway · Volume Gateway · Tape Gateway 세 가지를 중심에 둡니다.

먼저 대역폭으로 기간을 계산한다

전송 수단을 고르는 유일하게 신뢰할 수 있는 기준은 전송량 ÷ 실제 가용 대역폭 = 소요 기간입니다. 장비 모델과 용량을 외우는 것보다 이 계산이 먼저입니다.

  • 회선 속도가 아니라 업무에 지장을 주지 않는 여유 대역폭으로 계산합니다.
  • 계산 결과가 업무적으로 감당 가능한 기간이면 네트워크 전송(DataSync, 필요하면 전용 회선)입니다.
  • 감당할 수 없는 기간이 나오면 물리 전송을 검토합니다.
  • 대부분의 경우 초기 대량 이관 한 번과 이후의 증분 동기화는 다른 수단을 써도 됩니다.

물리 전송 장비 라인업은 최근 몇 년 사이 크게 축소되었습니다. 시중 자료가 아직 소개하는 일부 장비는 이미 제공되지 않으며, 현재는 신규 주문이 제한된 상태입니다. 특정 장비 모델과 용량을 외우는 것은 학습 가치가 낮습니다. 위의 "전송량 ÷ 가용 대역폭" 판단을 익히는 편이 실무와 시험 양쪽에서 유효합니다.

DataSync로 이관

DataSync는 온프레미스에 에이전트를 두고 원본 위치와 대상 위치를 정의한 뒤 작업(task)을 실행합니다. NFS · SMB · HDFS · 객체 스토리지를 원본으로 삼을 수 있고, Amazon S3 · Amazon EFS · Amazon FSx 4종을 대상으로 삼을 수 있습니다.

BytesPerSecond로 대역폭 상한을 두면 업무 시간에 회선을 다 쓰는 사고를 막을 수 있습니다(제약 2). 작업에 일정을 붙이면 야간에만 실행되게 할 수도 있습니다.

DataSync는 전송 후 검증을 수행하고, 파일 메타데이터 보존 여부와 삭제 반영 여부를 옵션으로 정합니다. "복사했는데 권한이 사라졌다"는 사고를 막으려면 메타데이터 옵션을 이관 전에 확인합니다.

전환 순서

무중단에 가깝게 전환하는 순서
순서 작업 확인 지점
1 대상 FSx 파일 시스템을 만들고 Active Directory에 조인한다 도메인 사용자가 SMB로 접근되는지
2 DataSync로 초기 전량 이관을 야간에 수행한다 전송 바이트와 검증 결과, 실패 목록

5단계가 제약 1의 핵심입니다. 장비 소프트웨어를 못 바꾼다면 이름이 같은 경로를 유지해야 하므로, 서버 이름을 DNS 별칭으로 옮기는 방식이 필요합니다. 새 경로를 알려 주고 각 장비를 재설정하는 계획은 이 제약에서 성립하지 않습니다.

자주 쓰지 않는 데이터의 처리

"최근 3개월만 자주 열린다"는 관찰은 계층화의 근거입니다. 오래된 도면을 S3로 내려 아카이브 클래스에 두면 고성능 파일 시스템의 용량을 줄일 수 있습니다. 보관 기간과 검색 지연 요구를 먼저 정하고 케이스 3 · S3 비용이 매달 늘어난다의 수명 주기 설계를 적용합니다.

  • AWS DataSync 사용 설명서 — 데이터 검증 옵션 — 전송 후 무결성 검증 방식
