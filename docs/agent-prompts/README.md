## 병렬 실행 방법

Wave 1·2·3은 **한 메시지에 모든 Agent 호출을 담아** 동시에 띄운다.

```
Agent(description="기본개념 ch02-04", prompt="<공통 프리앰블>\n\n<A1 프롬프트>")
Agent(description="기본개념 ch05-07", prompt="<공통 프리앰블>\n\n<A2 프롬프트>")
...
```

에이전트당 페이지 2~3개로 제한한다. 컨텍스트 초과로 중단되면 산출물이 통째로 날아간다.
**파일 하나를 완성한 뒤 다음으로 넘어가라**고 지시한다. 뒤로 갈수록 분량이 밀리므로
중요한 것을 먼저 끝내면 손실이 최소화된다.

## Wave 3의 원칙

**만든 사람이 검증하지 않는다.**

C1–C5는 **Write/Edit를 쓰지 않는다** (스크래치패드의 임시 스크립트는 예외).
발견 사항을 리포트로만 반환하고, 수정은 담당 에이전트에게 재지시해서 적용한다.

> 당신의 임무는 **틀린 것을 찾는 것**입니다.
> **"대체로 괜찮아 보인다"는 실패한 리뷰입니다.**
> 확신도를 CONFIRMED / PLAUSIBLE로 구분하고, 빈 리포트는 금지합니다.
> 검사했으나 문제가 없던 영역도 나열하세요.

### 리포트 형식 (강제)

```
## 요약
- 검사 범위: (파일 수, 항목 수)
- CRITICAL: N건 / MAJOR: N건 / MINOR: N건
- 검사했으나 문제 없던 영역: (나열)

## 발견 사항
### [CRITICAL-01] 제목
- 파일: path/to/file.html:123
- 현재: (인용)
- 문제: (무엇이 왜 틀렸는지)
- 근거: (FACT_SOURCES.md의 경로 또는 공식 문서 URL)
- 수정안: (구체적으로 무엇으로 바꿔야 하는지)
- 확신도: CONFIRMED | PLAUSIBLE
- 담당: (어느 에이전트가 고쳐야 하는지)
```

`담당` 필드가 있어야 수정 루프가 기계적으로 돌아간다.

### 심각도

| 등급 | 기준 |
|---|---|
| **CRITICAL** | 사실 오류 · 정답 오류 · 구식 정보를 현행으로 서술 · 요금 금액 기재 · CDN 참조 · 저작권 위반 · 사이트 파손 · SAA-C04 언급 |
| **MAJOR** | 오해를 부르는 서술 · 필수 토픽 누락 · 깨진 링크 · 접근성 차단 · 차트 수치 근거 없음 |
| **MINOR** | 표현 · 일관성 · 스타일 |

## 알려진 위험

| 위험 | 대응 |
|---|---|
| 콘텐츠 에이전트가 차트 에이전트보다 먼저 플레이스홀더를 넣음 | 검증기가 유예(WARN)를 준다. `--strict` 배포 빌드에서만 오류 |
| 다이어그램 카탈로그에 없는 ID 참조 | 검증기가 오류. 신규가 필요하면 **ID를 지어내지 말고 리포트에 요청**한다 |
| 에이전트끼리 같은 사실을 다르게 서술 | `FACT_SOURCES.md`가 정본. 충돌 시 그 문서를 갱신하고 날짜를 남긴다 |
| 확인 못 한 값을 그럴듯하게 채움 | 가장 위험한 실패 모드다. 반환 리포트의 "생략 항목"을 반드시 요구한다 |
