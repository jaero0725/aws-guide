# 다이어그램 카탈로그 (V1–V3 시각화 에이전트 계약서)

> 시각화는 **별도 트랙**이다. 콘텐츠 에이전트(A1–A9)와 시각화 에이전트(V1–V3)가
> 같은 파일을 다투지 않도록 다이어그램을 독립 SVG 파일로 분리하고,
> 콘텐츠는 플레이스홀더로만 참조한다.
>
> **함께 읽는 문서**: `PLAN.md` §1·§4-2·§5 · `docs/CONTENT_STYLE_GUIDE.md` §3-5 · `docs/FACT_SOURCES.md`
> **강제 주체**: `tools/validate.mjs`의 `checkDiagrams()` — 이 문서의 규칙은 전부 그 함수의 실제 코드에서 뽑았다.

---

## 1. 분리 구조 — 왜 나누는가

### 1-1. 콘텐츠 에이전트가 쓰는 것 — 플레이스홀더만

```html
<figure class="diagram" data-diagram="D-030">
  <figcaption>VPC 피어링의 비전이적 연결과 Transit Gateway 허브 구조 비교</figcaption>
</figure>
```

`data-diagram` 값과 `<figcaption>`만 쓴다. **`<svg>`를 직접 넣지 않는다.**

### 1-2. 시각화 에이전트가 쓰는 것 — 독립 SVG 파일만

```
assets/diagrams/D-030-peering-vs-tgw.svg
```

파일명은 **`{ID}-{slug}.svg`** 형식이다. 어기면 `validate.mjs`가 **ERROR**를 낸다.
`slug`는 영문 kebab-case로 짧게 쓴다.

### 1-3. 왜 이렇게 나누는가 (설계 근거)

Wave 1은 콘텐츠 9 + 시각화 3 + 차트 2 = **14개 에이전트가 동시에 돈다.**
만약 SVG를 HTML 안에 직접 그리게 하면 다음이 벌어진다.

- `basics/ch03.html` 한 파일을 콘텐츠 에이전트 A1과 시각화 에이전트 V1이 **동시에 쓴다.**
  두 에이전트의 쓰기가 겹치면 나중에 쓴 쪽이 상대의 작업을 통째로 날린다.
  에이전트에는 머지 도구가 없다. 충돌은 조용히 유실로 끝난다.
- 다이어그램 한 개를 고치려고 본문 수천 줄이 든 파일을 다시 써야 한다.
- 같은 다이어그램을 두 페이지에서 쓰려면 SVG를 복제해야 하고, 그 순간 둘이 갈라진다.

그래서 **파일 소유권을 배타적으로 자른다** (`PLAN.md` §5).

| 산출물 | 소유 | 절대 건드리지 않는 것 |
|---|---|---|
| `basics/*.html` 등 콘텐츠 HTML | A1–A9 | `assets/**`, `tools/**`, `docs/**` |
| `assets/diagrams/D-###-*.svg` | V1–V3 | **HTML 전부**, `assets/js/**`, `assets/css/**` |
| `assets/js/charts*.js`, `data/charts/*.json` | G1–G2 | **HTML 전부** |

> **시각화 에이전트는 HTML을 단 한 글자도 고치지 않는다.**
> 플레이스홀더가 없어서 SVG가 고아가 되면 리포트에 올린다. 직접 넣지 않는다.

### 1-4. 결합 방식 — 2단 바인딩

| 시점 | 방법 | 구현 |
|---|---|---|
| **개발 중 (런타임)** | `app.js`가 `figure.diagram[data-diagram]`을 찾아 `assets/diagrams/index.json`에서 ID→파일명을 조회하고 SVG를 fetch해 인라인 삽입 | `assets/js/app.js` |
| **배포 시 (빌드 타임)** | `tools/inline-diagrams.mjs`가 플레이스홀더를 실제 SVG로 **정적 치환** | `<figure … data-dg-inlined="1"><div class="dg-scroll"><svg …>` |

정적 치환을 하는 이유는 두 가지다.

1. `file://`로 열면 `fetch`가 차단되어 런타임 주입이 실패한다. 오프라인 학습이 요구사항이다.
2. **인라인이어야 CSS 변수(`--dg-*`)가 SVG 내부까지 닿는다.** `<img src="*.svg">`로 넣으면
   SVG는 별개 문서가 되어 페이지의 다크모드 토큰을 상속받지 못한다.

런타임 fetch는 **개발 편의용 폴백일 뿐**이다.

> ⚠️ **Wave 4의 `node tools/inline-diagrams.mjs` 실행은 필수다.**
> 이 단계를 건너뛰고 배포하면 다이어그램 자리가 **전부 빈 칸**으로 나간다
> (`app.js`의 fetch가 정적 호스팅에서는 동작할 수도 있지만, `file://`·CSP 환경에서는 실패한다).
> `node tools/validate.mjs --diagrams --deploy`가 미치환 플레이스홀더를 **ERROR**로 잡는다.
> 배포 전 반드시 이 조합으로 한 번 돌린다.

`assets/diagrams/index.json`은 `tools/build-index.mjs`가 생성한다.
**시각화 에이전트가 손으로 고치지 않는다.**

### 1-5. 인터랙티브 다이어그램의 로직은 어디에 두는가 — ⚠️ 미해결 소유권 항목

`assets/js/viz.js`의 REGISTRY 절이 인터랙티브 로직의 정본 위치다.
그런데 **`assets/js/**`는 Wave 0 소유이고 V1–V3의 배타 소유 경로가 아니다** (`PLAN.md` §5).

**기본 절차 (합의 전까지 이것을 따른다)**

1. V1–V3는 **SVG만 완성한다.** `data-dg` 훅과 **JS 없이도 의미가 성립하는 초기 상태**까지가 책임이다.
2. 각 인터랙티브 다이어그램에 대해 아래를 **리포트로 제출**한다.
   - `bindControls` 항목 명세 (`type` / `name` / `label` / 범위 / 기본값)
   - `data-dg` 이름 목록과 각 상태값(`on|off|active|done|error|pending|hidden`) 의미
   - `announce()`로 읽어 줄 안내 문장
3. **Wave 4(단독·순차)가 그 명세를 `viz.js` REGISTRY 절에 병합**한다. 단독 에이전트이므로 충돌하지 않는다.

Wave 0이 `viz.js`에 `viz-v1.js` / `viz-v2.js` / `viz-v3.js` 동적 로더를 추가하기로 결정하면
그때부터 각 V가 자기 파일을 소유한다. **그 전에는 `viz.js`를 직접 열지 않는다.**

## 2. 필수 SVG 규칙

`assets/css/viz.css`가 다이어그램 디자인 시스템의 정본이다. 모든 SVG는 그 토큰만 쓴다.

### 2-1. 정본 헤더 — 이 모양을 복사한다

```svg
<svg viewBox="0 0 720 340" role="img" aria-labelledby="d023-title d023-desc"
     class="ag-diagram" preserveAspectRatio="xMidYMid meet">
  <title id="d023-title">보안 그룹과 네트워크 ACL의 상태 저장 차이</title>
  <desc id="d023-desc">같은 요청과 응답 패킷이 서브넷 경계의 네트워크 ACL과 인스턴스 경계의
    보안 그룹을 통과하는 경로. 네트워크 ACL은 상태 비저장이므로 응답 트래픽을 임시 포트 범위로
    명시 허용해야 하고, 보안 그룹은 상태 저장이므로 별도 규칙 없이 응답이 돌아온다.</desc>

  <!-- 본문 -->
</svg>
```

| 항목 | 값 | 어기면 |
|---|---|:--:|
| `viewBox` | **필수.** 폭은 **720 고정**, 높이는 내용에 맞게 | 없으면 ERROR / 폭이 720이 아니면 WARN |
| `width` / `height` 속성 | **루트에 쓰지 않는다** | **ERROR** (각각 별도) |
| `role="img"` | 필수 | **ERROR** |
| `<title>` | 필수. 다이어그램 제목 한 줄 | **ERROR** |
| `<desc>` | 필수. **그림을 못 보는 사람이 결론까지 알 수 있게** 2~3문장 | **ERROR** |
| `aria-labelledby` | 필수 (`aria-label`도 인정). `<title>`·`<desc>`의 id를 가리킨다 | **ERROR** |
| `class="ag-diagram"` | 필수. **`kg-diagram`이 아니다** (sibling 프로젝트 잔재) | WARN |

> `id`를 `<title>`·`<desc>`에 쓰는 것은 안전하다. `inline-diagrams.mjs`가 인라인 시
> 모든 `id`에 `{id소문자}-{페이지내순번}-` 접두어를 붙이면서 `aria-labelledby`·`aria-describedby`·
> `href="#…"`·`url(#…)` 참조를 **함께 갱신**한다. 같은 페이지에 같은 다이어그램이 두 번 들어와도 충돌하지 않는다.
> **단, JS가 잡는 훅은 예외다 — §2-4를 반드시 읽는다.**

### 2-3. 색 — 하드코딩은 ERROR

**허용되는 것은 `viz.css`의 `--dg-*` 토큰과 `currentColor`뿐이다.**

```svg
<!-- bad  -->  <rect fill="#f4f6f9" stroke="#4d5764"/>
<!-- bad  -->  <text fill="black">…</text>
<!-- bad  -->  <path stroke="rgba(18,86,160,.4)"/>
<!-- good -->  <rect class="dg-node"/>
<!-- good -->  <rect fill="var(--dg-accent-soft)" stroke="var(--dg-accent)" stroke-width="var(--dg-sw-2)"/>
<!-- good -->  <path class="dg-edge dg-edge--danger" marker-end="url(#d023-arrow-danger)"/>
```

검증기가 잡는 형태는 정확히 다섯 가지다. 색을 받는 속성은
`fill` · `stroke` · `stop-color` · `color` · `flood-color` · `lighting-color` 여섯 개다.

| # | 검출 형태 | 예 |
|:--:|---|---|
| 1 | 색 속성 = hex | `fill="#3b82f6"`, `stroke='#fff'`, `stop-color="#1256a0"` |
| 2 | 선언문의 hex | `style="fill: #fff"`, `<style>` 안의 `stroke: #000` |
| 3 | 색 속성 = 명명 색 | `black white red blue green yellow orange purple gray grey silver navy teal lime aqua fuchsia maroon olive` |
| 4 | `rgb()` / `rgba()` | 어디에 있든 걸린다 |
| 5 | `hsl()` / `hsla()` | 〃 |

> **오탐 걱정은 하지 않아도 된다.** `href="#d023-lane"`이나 `url(#d023-arrow)` 같은
> 내부 조각 참조는 "색을 받는 자리"가 아니므로 걸리지 않는다.
> 반대로 `fill="url(#d023-grad)"`는 통과한다 — 그라디언트를 쓰려면 `<stop>`의 색이
> `var(--dg-*)`여야 한다.

**다크모드**는 토큰만 쓰면 자동으로 따라온다. `viz.css`가 라이트/다크/명시적 테마 3벌을 정의한다.
`#fff`를 한 번 쓰는 순간 다크모드에서 그 도형만 하얗게 남는다.

### 2-4. 사용 가능한 토큰과 유틸리티 클래스 — `viz.css` 실물 전량

**여기 없는 토큰·클래스는 존재하지 않는다.** `viz.css`는 Wave 0 소유라 추가할 수 없다.
필요한 것이 없으면 만들지 말고 리포트에 올린다.

**색 토큰 (17종)**

| 토큰 | 용도 |
|---|---|
| `--dg-stroke` | 기본 선·테두리 |
| `--dg-fill` | 노드 배경 |
| `--dg-fill-alt` | 보조 노드 배경 (대비용) |
| `--dg-accent` | 강조 · 핵심 경로 |
| `--dg-muted` | 비활성 · 배경 요소 |
| `--dg-danger` | 실패 · 유실 · 차단 지점 |
| `--dg-ok` | 성공 · 정상 경로 |
| `--dg-warn` | 주의 |
| `--dg-text` | 다이어그램 텍스트 |
| `--dg-text-muted` | 보조 레이블 |
| `--dg-grid` | 눈금 · 보조선 |
| `--dg-bg` | 캔버스 배경 (기본 `transparent` — 건드리지 않는다) |
| `--dg-accent-soft` · `--dg-ok-soft` · `--dg-warn-soft` · `--dg-danger-soft` · `--dg-muted-soft` | 각 색 노드의 `fill` |

**기하 토큰**

| 토큰 | 값 | 용도 |
|---|---|---|
| `--dg-sw-hair` | 0.75 | 눈금·보조선 전용 |
| `--dg-sw-1` | 1.5 | 기본 선 |
| `--dg-sw-2` | 2.5 | 강조 경로 |
| `--dg-dash-1` | `5 3` | 일반 파선 |
| `--dg-dash-2` | `2 2` | 점선 |
| `--dg-dash-3` | `9 4 2 4` | 일점쇄선 |
| `--dg-radius` | 4 | 노드 모서리 |
| `--dg-min-w` | 720px | 좁은 화면에서 축소 대신 스크롤할 최소 폭 |

**유틸리티 클래스 (`svg.ag-diagram` 하위에서만 동작)**

| 분류 | 클래스 |
|---|---|
| 글자 크기 | `.dg-fs-sm` 13px · `.dg-fs-md` 15px · `.dg-fs-lg` 18px · `.dg-fs-xl` 22px |
| 글자 변형 | `.dg-bold` · `.dg-mono` · `.dg-muted` · `.dg-num`(자릿수 정렬) |
| 노드 | `.dg-node` · `.dg-node--alt` · `.dg-node--accent` · `.dg-node--danger` · `.dg-node--ok` · `.dg-node--warn` · `.dg-node--muted` · `.dg-node--empty` · `.dg-node--done` |
| 연결선 | `.dg-edge` · `.dg-edge--accent` · `.dg-edge--danger` · `.dg-edge--ok` · `.dg-edge--warn` · `.dg-edge--muted` · `.dg-edge--dashed` · `.dg-edge--dotted` · `.dg-edge--dashdot` |
| 보조 | `.dg-grid`(눈금) · `.dg-panel`(점선 그룹 경계) · `.dg-x`(유실·차단 X 표시) |
| 화살촉 | `.dg-marker` · `.dg-marker--accent` · `.dg-marker--danger` · `.dg-marker--ok` · `.dg-marker--warn` · `.dg-marker--muted` (`<marker>` 안의 `<path>`에 붙인다) |
| 히트 영역 | `.dg-hit` (투명 클릭 영역) |

`.dg-scroll`은 `app.js` / `inline-diagrams.mjs`가 SVG를 감싸며 주입하는 래퍼다.
**SVG 파일 안에 쓰지 않는다.** 파일에는 `<svg>` 루트만 있다.

**좌표계와 글자 크기의 관계 — 13px가 왜 하한인가**

`viz.css`는 780px 미만 화면에서 SVG를 축소하지 않고 `--dg-min-w`(720px)로 **가로 스크롤**시킨다.
즉 720 좌표계가 1:1로 렌더링되므로 `.dg-fs-sm`은 실제 13px가 된다.
13 미만을 쓰면 그대로 못 읽는 글자가 된다. 그래서 ERROR다.

### 2-5. 선·패턴·레이블

- 선 굵기는 **0.75 / 1.5 / 2.5 세 값만** 쓴다. 클래스를 쓰면 자동으로 지켜진다.
  직접 쓸 때는 `stroke-width="var(--dg-sw-1)"` 형태로 토큰을 참조한다.
- **색만으로 구분하지 않는다.** 색 + 파선 패턴 + 텍스트 레이블을 병기한다.
  라이트/다크 전환, 흑백 인쇄, 색각 이상 어느 쪽에서도 정보가 살아야 한다.
- 텍스트는 반드시 `<text>`로 넣는다. 글자를 도형으로 굽지 않는다(검색·확대·낭독이 죽는다).
- 한국어로 쓴다. 단 AWS 서비스 정식 명칭과 설정 키는 원문 그대로다
  (`Amazon S3`, `NAT Gateway`, `ObjectOwnership`).
- 이모지를 쓰지 않는다 (`CONTENT_STYLE_GUIDE.md` §6).
  이 카탈로그의 🖱 표기는 문서 편의용이며 산출물에는 들어가지 않는다.

### 2-6. 인터랙티브 다이어그램 규칙

| # | 규칙 | 이유 |
|:--:|---|---|
| 1 | **조작 대상은 `id`가 아니라 `data-dg` 속성으로 표시한다** | `inline-diagrams.mjs`가 모든 `id`에 접두어를 붙인다. `#node-3` 셀렉터는 인라인 후 **반드시 깨진다** |
| 2 | 로직은 `viz.js` REGISTRY에 등록한다 (§1-5 절차) | SVG 안 `<script>`는 이중 실행·CSP 위반·검증 ERROR |
| 3 | 컨트롤은 `ctx.bindControls`로만 만든다 | 실제 `<button>`/`<input>`/`<select>`가 생성되어 키보드 조작이 보장된다. `div` + click 핸들러 금지 |
| 4 | 상태는 `ctx.setState(name, state)`로만 바꾼다 | 스타일링은 `viz.css`가 `[data-state]`로 처리한다. SVG 속성을 직접 칠하면 다크모드가 깨진다 |
| 5 | **JS 없이도 초기 상태가 의미를 전달해야 한다** | progressive enhancement. 정적 인라인만 된 상태로도 다이어그램이 성립할 것 |
| 6 | 애니메이션은 `prefers-reduced-motion`을 존중한다 | `ctx.reducedMotion`으로 분기하고, `animateAlong`은 즉시 끝점으로 이동한다. `viz.css`가 transition도 제거한다 |
| 7 | 상태 변화는 `ctx.announce()`로 문장 안내한다 | `.dg-live`(`role="status"`, `aria-live="polite"`)에 들어간다. 시각 변화만으로는 스크린 리더에 아무것도 전달되지 않는다 |

**`data-state` 어휘 — 이 7개만 쓴다** (`viz.css`가 정의하는 값)

| 값 | 의미 | 시각 효과 |
|---|---|---|
| `on` | 켜짐·선택됨 | accent 배경/테두리 |
| `off` | 꺼짐·해당 없음 | 투명도 0.32 |
| `active` | 지금 동작 중인 경로 | accent + 굵은 선 |
| `done` | 완료·성공 | ok 배경/테두리 |
| `error` | 실패·차단 | danger 배경/테두리 |
| `pending` | 대기 중 | 투명도 0.6 |
| `hidden` | 감춤 | 투명도 0, 포인터 이벤트 없음 |

**`ctx` API 요약** (`assets/js/viz.js` 실물)

```
ctx.q(name) / ctx.qa(name)     data-dg 로 조회 (단일 / 전체)
ctx.qs(sel) / ctx.qsa(sel)     임의 CSS 셀렉터
ctx.setState(target, state)    data-state 부여 · null 이면 제거
ctx.text(name, str)            <text data-dg="name"> 내용 교체
ctx.attr(name, obj)            속성 일괄 설정
ctx.move(name, x, y)           transform: translate
ctx.animateAlong(path, opts)   경로 따라 이동 (reduced-motion 시 즉시 이동)
ctx.bindControls(spec)         컨트롤 생성 → { values, get, set, reset, announce, readout }
ctx.announce(text)             aria-live 안내
ctx.readout(items)             [{label, value}] 상태 표시
ctx.reducedMotion              boolean
```

컨트롤 항목 타입은 `range` · `number` · `select` · `toggle` · `button` · `reset` 여섯 가지다.

### 4-3. 소유권 규칙 (위반 시 작업 유실)

1. **각 V는 자기 ID 대역의 `.svg` 파일만 만든다.** 다른 대역의 파일을 고치지 않는다.
2. **HTML을 열지 않는다.** 플레이스홀더가 없어 SVG가 고아가 되면 리포트에 올린다.
3. **`assets/css/viz.css` · `assets/js/viz.js` · `assets/diagrams/index.json`을 고치지 않는다.**
   토큰이나 클래스가 부족하면 만들지 말고 리포트에 올린다. (인터랙티브 로직은 §1-5 절차)
4. **이 카탈로그에 없는 ID로 파일을 만들지 않는다.** `validate.mjs`가 **ERROR**를 낸다.
   반대로 카탈로그에 행이 있으면 그 ID는 유효하다.
   > 이 파일의 `D-###` 문자열이 곧 유효 ID 목록이다(`loadCatalogIds()`).
   > 그래서 §3의 예약 번호는 일부러 `D-` 접두어 없이 적었다.
   > **예약 번호를 실제로 쓰려면 §3의 해당 표에 행을 먼저 추가**해야 한다. 순서를 바꾸면 검증에서 막힌다.
5. 작업 종료 전 반드시 실행한다.
   ```bash
   node tools/validate.mjs --diagrams
   node tools/validate.mjs --diagrams --strict   # 고아·미참조까지 오류로
   ```
