서비스 한 줄 정의

시험 범위 서비스를 카테고리별로 모아 한 줄 정의와 언제 고르는가만 남긴 표입니다. 문항에서 처음 보는 이름이 나왔을 때 그 자리에서 정체를 확인하고, 선택지 다섯 개 중 애초에 후보가 아닌 것을 빠르게 걷어 내는 용도입니다.

아래 시험 범위 밖 서비스 절도 함께 보십시오. 공부하지 않아도 되는 것을 아는 것이 이 페이지에서 가장 값이 큰 부분입니다.

이 페이지 쓰는 법

  • 표마다 있는 검색 상자에 서비스명이나 키워드를 넣어 행을 걸러 낼 수 있습니다. Esc로 초기화됩니다.
  • 세 번째 열 언제 고르는가만 세로로 훑으면 선택 신호 목록으로 읽힙니다.
  • 정의가 잘 안 떠오르는 서비스는 이름만 보고 나머지 두 칸을 스스로 말한 뒤 대조하십시오.
  • 두 서비스 중 무엇을 고를지가 문제라면 헷갈리는 쌍 비교로 넘어갑니다.
  • 요구사항에서 출발해 서비스를 찾아 내려가려면 서비스 선택 결정 트리를 씁니다.

읽는 규칙 세 가지

이 표는 서비스를 설명하지 않습니다. 설명은 각 챕터가 합니다. 여기서 하는 일은 문항의 선택지에 등장한 이름을 범주로 환원하는 것입니다. 범주가 잡히면 요구사항과 맞지 않는 선택지는 그 자리에서 사라집니다.

표를 읽을 때 지킬 세 가지 규칙
규칙 이유
접두사를 바꿔 쓰지 않습니다 서비스마다 Amazon과 AWS 중 하나가 정해져 있습니다. Amazon S3, AWS Lambda가 맞고 그 반대는 틀린 표기입니다. 문항의 선택지는 정식 명칭으로 나옵니다
한 줄 정의는 담당 문제로 씁니다 "관리형 NoSQL 데이터베이스"보다 "키로 접근하는 워크로드를 무제한에 가깝게 확장한다"가 선택에 쓰입니다. 시험은 기능 목록이 아니라 요구사항을 줍니다
범위 밖 서비스는 후보에서 뺍니다 AWS가 명시적으로 범위 밖으로 지정한 서비스는 정답으로 요구되지 않습니다. 선택지에 등장할 수는 있으므로 이름은 알되 공부하지는 않는 것이 정확한 전략입니다

컴퓨팅

컴퓨팅 서비스 — 한 줄 정의와 선택 신호
서비스 한 줄 정의 언제 고르는가
Amazon EC2 운영체제 수준까지 우리가 통제하는 가상 서버입니다 특정 운영체제·커널·라이선스가 필요하거나, 기존 서버를 그대로 옮겨야 할 때. 반대로 "운영 부담 최소"가 한정어면 후보에서 내려갑니다
Amazon EC2 Auto Scaling 인스턴스 수를 수요에 맞춰 늘리고 줄이며, 비정상 인스턴스를 교체합니다 부하가 변하거나, 인스턴스 장애를 자동 복구해야 할 때. 다중 가용 영역 배치와 함께 나옵니다
Elastic Load Balancing 들어오는 트래픽을 여러 대상에 분산하고 비정상 대상을 뺍니다 단일 진입점이 필요하거나 다중 가용 영역으로 나눠 보내야 할 때. 세부 선택은 ALB · NLB · GWLB 비교
AWS Lambda 서버를 두지 않고 이벤트에 반응해 코드를 실행합니다 간헐적·이벤트 구동 처리이고 "운영 부담 최소"가 한정어일 때. 실행 시간 상한이 요구를 넘으면 다른 컴퓨팅으로 갑니다
AWS Fargate 컨테이너를 실행하는 서버리스 용량 제공 방식입니다. 그 자체로 별도의 오케스트레이터가 아닙니다 컨테이너는 쓰되 인스턴스를 관리하고 싶지 않을 때. Amazon ECS 또는 Amazon EKS와 함께 씁니다
Amazon ECS AWS 고유의 컨테이너 오케스트레이터입니다 컨테이너를 굴려야 하는데 Kubernetes API가 요구되지 않을 때. 가장 단순한 관리형 경로입니다
Amazon EKS 관리형 Kubernetes 컨트롤 플레인입니다 문제문이 Kubernetes를 명시하거나 기존 Kubernetes 자산을 옮겨야 할 때
Amazon ECR 컨테이너 이미지를 저장하는 관리형 레지스트리입니다 컨테이너 문항에서 이미지 저장·스캔 위치를 물을 때
AWS Batch 배치 작업을 큐에 넣고 컴퓨팅 환경을 자동으로 준비해 실행합니다 대량의 독립 작업을 시간에 구애받지 않고 처리할 때. 스팟 용량과 잘 맞습니다
AWS Elastic Beanstalk 코드를 올리면 EC2 · 로드 밸런서 · Auto Scaling 구성을 대신 만들어 줍니다 애플리케이션 코드는 그대로 두고 배포·용량 관리만 넘기고 싶을 때
Amazon Lightsail 단순한 웹 서비스를 묶음 구성으로 제공합니다 소규모·단순 워크로드이고 세밀한 네트워크 제어가 필요 없을 때
AWS Outposts AWS 인프라를 고객 데이터센터 안에 설치해 같은 API로 씁니다 데이터가 물리적으로 특정 시설을 떠날 수 없거나 온프레미스 시스템과 극히 낮은 지연이 필요할 때
AWS Local Zones 리전 밖 도시 인접 위치에 컴퓨팅과 스토리지를 배치합니다 특정 대도시 사용자에게 리전보다 더 낮은 지연이 필요할 때
AWS Wavelength 통신 사업자 네트워크 안에 컴퓨팅을 배치합니다 모바일 단말이 코어 네트워크를 나가지 않고 도달해야 할 때

스토리지

스토리지 서비스 — 한 줄 정의와 선택 신호
서비스 한 줄 정의 언제 고르는가
Amazon S3 객체를 키로 저장하는 오브젝트 스토리지입니다. 파일 시스템이 아니라 키-값 저장소입니다 정적 자산 · 백업 · 로그 · 데이터 레이크처럼 통째로 읽고 쓰는 데이터. 부분 수정이 잦은 데이터에는 맞지 않습니다
Amazon S3 Glacier 스토리지 클래스 접근이 드문 데이터를 위한 S3의 아카이브 계층 세 가지입니다 보존은 해야 하지만 거의 읽지 않을 때. 필요한 검색 시간이 클래스를 가릅니다
Amazon EBS EC2 인스턴스에 붙이는 네트워크 블록 볼륨입니다. 인스턴스와 수명이 분리됩니다 운영체제 디스크, 데이터베이스 데이터 파일처럼 블록 단위 임의 접근이 필요할 때
EC2 인스턴스 스토어 호스트에 직접 붙은 임시 디스크입니다 캐시·스크래치처럼 사라져도 되는 데이터에 최고 성능이 필요할 때. 인스턴스를 중지하면 사라집니다
Amazon EFS 여러 리눅스 인스턴스가 동시에 마운트하는 NFS 파일 시스템입니다 가용 영역을 넘어 여러 대가 같은 파일을 읽고 써야 할 때. 코드를 고치지 않고 공유가 필요할 때
Amazon FSx for Windows File Server SMB 프로토콜과 Active Directory 통합을 제공하는 관리형 Windows 파일 서버입니다 문제문에 Windows · SMB · Active Directory가 있을 때
Amazon FSx for Lustre 고성능 컴퓨팅용 병렬 파일 시스템이며 S3와 연동됩니다 문제문에 HPC · 머신러닝 학습 · 대규모 병렬 처리가 있을 때
Amazon FSx for NetApp ONTAP ONTAP 기능을 그대로 제공하며 NFS · SMB · iSCSI를 함께 씁니다 기존 NetApp 환경을 기능 손실 없이 옮겨야 할 때, 여러 프로토콜을 동시에 써야 할 때
Amazon FSx for OpenZFS OpenZFS 기반 NFS 파일 시스템입니다 기존 ZFS·리눅스 NFS 환경을 옮기면서 스냅샷·복제 기능을 유지할 때
AWS Storage Gateway 온프레미스에서 익숙한 프로토콜로 접근하되 실제 데이터는 AWS에 두는 하이브리드 게이트웨이입니다 온프레미스 애플리케이션을 그대로 두고 저장 용량만 클라우드로 옮길 때
AWS Backup 여러 서비스의 백업을 정책 하나로 중앙에서 관리합니다 "백업 정책을 조직 전체에 일관되게 적용", "보존 규정을 증명"이 요구일 때
Amazon Data Lifecycle Manager EBS 스냅샷과 AMI의 생성·보존·삭제를 일정으로 자동화합니다 EBS 스냅샷만 주기적으로 돌리면 되는 좁은 요구일 때

스토리지 문항은 거의 언제나 블록 · 파일 · 객체 중 어느 계열인지를 먼저 물어봅니다. "여러 서버가 동시에" 라는 말이 있으면 파일 계열, "인스턴스에 붙여서" 면 블록, "정적 자산 · 백업 · 아카이브" 면 객체입니다. 이 판단을 분기 형태로 정리한 것이 스토리지 결정 트리입니다.

데이터베이스

데이터베이스 · 캐시 서비스 — 한 줄 정의와 선택 신호
서비스 한 줄 정의 언제 고르는가
Amazon RDS 관계형 데이터베이스 엔진을 관리형으로 제공합니다. 백업·패치·장애 조치를 AWS가 맡습니다 SQL과 트랜잭션이 필요하고 기존 엔진을 그대로 써야 할 때
Amazon Aurora MySQL · PostgreSQL과 호환되며 여러 가용 영역에 걸친 공유 스토리지 위에서 동작합니다 읽기 확장과 빠른 장애 조치를 함께 요구할 때. 복제본이 읽기와 승격 대상을 겸합니다
Amazon Aurora Serverless v2 Aurora 용량을 부하에 따라 자동으로 조정합니다 부하가 간헐적·예측 불가이고 인스턴스 크기를 고정하기 어려울 때
Amazon RDS Proxy 데이터베이스 연결을 풀링해 재사용합니다 Lambda 등 동시 실행이 급증하는 클라이언트가 연결 수를 고갈시킬 때
Amazon DynamoDB 키로 접근하는 관리형 NoSQL이며 규모에 따라 자동으로 분할됩니다 접근 패턴이 키 조회로 고정되고, 예측 가능한 지연과 사실상 무제한 확장이 필요할 때. "운영 부담 최소" 한정어와 잘 맞습니다
Amazon DynamoDB Accelerator (DAX) DynamoDB 전용 인메모리 캐시이며 DynamoDB API와 호환됩니다 DynamoDB 읽기 지연을 코드 변경을 최소화하며 줄일 때
Amazon ElastiCache Redis 또는 Memcached 엔진을 관리형으로 제공하는 범용 인메모리 캐시입니다 관계형 데이터베이스의 반복 조회, 세션 저장, 순위표처럼 임의의 데이터를 캐시할 때
Amazon MemoryDB 내구성 있는 인메모리 데이터베이스입니다. 캐시가 아니라 주 저장소로 씁니다 인메모리 속도가 필요하면서 데이터가 사라지면 안 될 때
Amazon Redshift 열 기반 저장과 병렬 처리를 쓰는 데이터 웨어하우스입니다 대량 데이터를 대상으로 반복적인 복잡한 분석 질의를 돌릴 때
Amazon DocumentDB MongoDB 호환 문서 데이터베이스입니다 문제문에 MongoDB가 명시될 때
Amazon Neptune 그래프 데이터베이스입니다 문제문에 관계 · 소셜 그래프 · 추천 · 지식 그래프가 있을 때
Amazon Keyspaces Apache Cassandra 호환 관리형 데이터베이스입니다 문제문에 Cassandra가 명시될 때
Amazon Timestream 시계열 데이터에 특화된 데이터베이스입니다 센서·지표처럼 시간축으로 쌓이는 데이터를 저장하고 질의할 때

네트워킹과 콘텐츠 전송

네트워킹 · 콘텐츠 전송 서비스 — 한 줄 정의와 선택 신호
서비스 한 줄 정의 언제 고르는가
Amazon VPC 계정 안에 만드는 논리적으로 격리된 네트워크입니다 모든 네트워크 문항의 무대입니다. 서브넷이 가용 영역 하나에 묶인다는 사실이 다중 가용 영역 설계의 출발점입니다
인터넷 게이트웨이 VPC와 인터넷을 잇는 수평 확장형 관문입니다 서브넷을 퍼블릭으로 만들 때. 이 게이트웨이 자체는 이중화를 걱정하지 않아도 됩니다
NAT 게이트웨이 프라이빗 서브넷의 아웃바운드만 허용하는 주소 변환 장치입니다 프라이빗 인스턴스가 인터넷으로 나가기만 해야 할 때. 가용 영역마다 하나씩 둡니다
보안 그룹 인스턴스(ENI) 수준의 상태 저장 방화벽이며 허용 규칙만 있습니다 "이 인스턴스에 누가 접근할 수 있는가"를 정할 때. 차단은 할 수 없습니다
네트워크 ACL 서브넷 수준의 상태 비저장 필터이며 허용과 거부를 모두 씁니다 특정 주소를 거부해야 하거나 서브넷 전체에 공통 규칙을 걸 때
VPC 게이트웨이 엔드포인트 라우팅 테이블 항목으로 Amazon S3와 Amazon DynamoDB에 비공개로 접근합니다 두 서비스로 향하는 트래픽을 인터넷과 NAT 게이트웨이 밖으로 빼낼 때
VPC 인터페이스 엔드포인트 (AWS PrivateLink) 서브넷 안에 ENI를 만들어 그 사설 주소로 서비스에 접근합니다 게이트웨이 엔드포인트가 지원하지 않는 서비스, 또는 다른 계정이 제공하는 서비스에 비공개로 접근할 때
VPC 피어링 두 VPC를 일대일로 잇습니다 연결해야 할 VPC가 소수이고 전이 라우팅이 필요 없을 때
AWS Transit Gateway VPC와 온프레미스 연결을 허브 하나로 모읍니다 연결 대상이 많아 피어링이 조합 폭발을 일으킬 때, 전이 라우팅이 필요할 때
AWS Site-to-Site VPN 인터넷 위에 IPsec 암호화 터널을 만듭니다 빠르게 연결해야 하거나, 전용 회선의 백업 경로가 필요할 때
AWS Client VPN 개별 사용자 단말을 VPC에 연결합니다 사무실이 아니라 개인 단말이 프라이빗 리소스에 접근해야 할 때

시험 범위 밖 서비스 — 공부하지 않습니다

아래는 AWS가 SAA-C03 시험 가이드에서 범위 밖(out of scope)으로 명시한 영역입니다. 선택지에 이름이 등장할 수는 있지만, 이 서비스를 깊이 알아야 풀리는 문항은 출제되지 않습니다. 학습 시간을 여기에 쓰지 마십시오. 이름과 한 줄 정체만 알아 두고, 선택지에 보이면 그 자체를 근거로 후보에서 낮추면 됩니다.

AWS CloudFormation은 범위 안, AWS CDK는 범위 밖

학습자가 가장 자주 시간을 낭비하는 지점입니다. 두 도구가 실무에서 함께 쓰이기 때문에 나란히 공부하게 되는데, 시험 범위는 둘로 갈립니다.

AWS CloudFormation과 AWS CDK의 시험 범위 구분
항목 AWS CloudFormation AWS CDK
시험 범위 범위 안 — 정식 학습 대상 범위 밖 — 학습 대상 아님
정의 방식 템플릿(JSON · YAML)으로 선언합니다 프로그래밍 언어 코드로 작성해 템플릿을 생성합니다
실행 주체 AWS가 스택으로 생성·갱신·롤백을 수행합니다 최종적으로는 CloudFormation이 실행합니다
시험에서의 취급 스택 · 변경 세트 · 드리프트 감지 · 롤백을 물을 수 있습니다 선택지에 이름이 보이면 정답 후보로 올리지 않습니다

Aurora DSQL, S3 Tables, S3 Vectors처럼 최근에 나온 서비스도 같은 취급입니다. 이름은 접하게 되지만 SAA-C03 학습 대상이 아닙니다. 시험 대비 시간에는 범위 안 서비스의 판단 기준을 반복하는 편이 이득이 큽니다.
