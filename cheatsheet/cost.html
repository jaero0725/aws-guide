요금 구조와 절감

비용 문항은 계산기를 요구하지 않습니다. 구조적으로 더 싼 안을 고르게 합니다. 그래서 금액을 몰라도 과금 축과 방향성만 알면 판단이 됩니다.

이 페이지는 금액을 싣지 않습니다. 요금은 리전과 시점에 따라 달라져 학습 자료에 고정할 값이 아닙니다. 서술은 언제나 과금 여부 · 과금 축 · 상대 비교 세 가지로만 합니다.

이 페이지 쓰는 법

  • 비용 문항을 만나면 과금 축부터 봅니다. 설계 변경이 어느 축을 건드리는지가 판단입니다.
  • 데이터 전송 방향성 표는 통째로 외우십시오. 비용 사고 대부분이 이 표의 한 줄에서 납니다.
  • 절감 레버는 순서가 중요합니다. 위에서부터 적용합니다.
  • 도구 이름을 묻는 문항은 비용 가시성 절의 역할 구분으로 갈립니다.
  • 자세한 설명과 다이어그램은 18장에 있습니다. 이 페이지는 그 요약입니다.

금액 없이 판단하는 법

구체적인 금액을 싣지 않습니다. 요금은 리전과 시점에 따라 달라지고, 시험도 금액을 묻지 않기 때문입니다. 실제 금액이 필요하면 AWS 요금 페이지와 AWS Pricing Calculator에서 확인하고, 이미 쓰고 있는 계정의 값은 Cost Explorer와 Cost and Usage Report에서 봅니다.

금액을 몰라도 판단할 수 있는 이유는, AWS 요금이 서비스마다 정해진 몇 개의 축으로만 매겨지기 때문입니다. 어떤 설계 변경이 어느 축을 건드리는지 알면 방향은 결정됩니다. "이 구성은 무엇으로 과금되는가"가 비용 문항의 유일한 질문입니다.

단계 확인할 것 이 단계에서 소거되는 선택지
1. 제약을 위반하는가 가용성 · 지연 · 규정 요구를 깨는 안인지 운영 데이터베이스를 스팟 인스턴스에 올리는 안, 규정을 어기고 리전을 옮기는 안

3. 그 축을 실제로 줄이는가 경로를 바꿔 장치를 아예 지나지 않게 하는지, 단가만 낮추는지 쓰지 않아도 될 자원을 약정으로 싸게 사는 안

AWS Lambda 호출 수 · 실행 시간 · 할당 메모리 간헐적 부하에 유리하고, 상시 고부하에서는 오히려 비쌀 수 있습니다

Amazon RDS 인스턴스 가동 시간 · 저장 용량 · 백업 · 데이터 전송 Multi-AZ 배포는 가용성을 사면서 컴퓨팅 비용도 함께 늘립니다
Elastic Load Balancing 가동 시간 · 처리 단위 트래픽이 없어도 시간 요금이 붙습니다. 쓰지 않는 로드 밸런서는 삭제 대상입니다
Amazon CloudFront 송신 데이터 · 요청 수 오리진 송신을 줄여 전체 전송 비용을 낮추는 것이 도입 근거입니다
AWS KMS 키 개수 · API 호출 수 대량 객체를 SSE-KMS로 다룰 때 호출 수가 늘어납니다. S3 버킷 키가 호출을 줄입니다
탄력적 IP 가동 시간(미연결 상태 포함) 인스턴스에 붙이지 않고 남겨 둔 주소가 대표적인 낭비입니다

데이터 전송의 방향성

데이터 전송은 양이 아니라 방향으로 요금이 정해집니다. 이 비대칭 하나가 비용 도메인 문항의 상당수를 설명합니다.

데이터 전송 방향별 과금 여부와 설계 함의 — 금액이 아니라 방향만 다룹니다
방향 과금 설계에 주는 함의
인터넷에서 AWS로 (수신) 대체로 무료 올리는 것은 대체로 비용 요인이 아닙니다. "업로드 비용을 줄인다"는 선택지는 대체로 무의미합니다
AWS에서 인터넷으로 (송신) 과금 가장 큰 전송 비용 항목입니다. 송신량 자체를 줄이거나 CloudFront로 캐시해 오리진 송신을 줄입니다
같은 가용 영역, 사설 IP 가장 저렴한 경로 퍼블릭 IP나 인터넷 경유로 우회하지 않도록 사설 주소로 통신하게 합니다
같은 리전, 가용 영역 간 과금 다중 가용 영역은 가용성을 사면서 전송 비용을 함께 부릅니다. 대량 트래픽이 불필요하게 가용 영역을 넘지 않게 배치합니다
리전 간 과금 교차 리전 복제, 리전 간 백업, 다중 리전 재해 복구는 언제나 전송 비용을 동반합니다
NAT 게이트웨이 경유 시간 요금 + 처리 데이터 요금 목적지가 어디든 통과한 모든 데이터에 처리 요금이 붙습니다. 지나지 않게 만드는 것이 유일한 절감입니다

데이터 전송 문항의 확인 순서는 셋입니다. (1) 트래픽이 인터넷으로 나가는가 — CloudFront 캐싱으로 오리진 송신을 줄입니다. (2) 가용 영역이나 리전을 넘는가 — 넘지 않아도 되는 트래픽이면 배치를 고칩니다. (3) NAT 게이트웨이를 지나는가 — AWS 서비스가 목적지라면 VPC 엔드포인트로 경로를 바꿉니다.

절감 레버 — 순서가 있습니다

레버는 위에서부터 적용합니다. 쓰지 않아도 될 자원을 약정으로 싸게 사는 것은 절감이 아닙니다. 순서를 지키지 않은 선택지는 그 자체로 소거 대상이 됩니다.

절감 레버의 적용 순서
순서 레버 구체적인 행동
1 없애기 — 항상 켜져 있는데 거의 안 쓰는 것 유휴 NAT 게이트웨이, 연결되지 않은 EBS 볼륨과 탄력적 IP, 트래픽 없는 로드 밸런서, 오래된 스냅샷
2 끄기 — 쓸 때만 켜기 개발·테스트 환경의 야간·주말 중지, 일정 기반 Auto Scaling
3 경로 바꾸기 — 과금 장치를 지나지 않게 VPC 엔드포인트, CloudFront 캐싱, 가용 영역을 넘지 않는 배치
4 계층 옮기기 — 접근 빈도에 맞는 클래스로 S3 수명 주기 규칙, EBS 볼륨 타입 조정, 오래된 로그의 보존 정책
5 라이트사이징 — 실사용에 맞추기 AWS Compute Optimizer의 권고 적용, 과도한 프로비저닝된 IOPS 축소
6 모델 바꾸기 — 사용량에 비례하게 서버리스 전환, DynamoDB 온디맨드 모드, Aurora Serverless v2
7 약정하기 — 남은 기저 부하의 단가 낮추기 Savings Plans, 예약 인스턴스, 중단 가능한 부분은 스팟 인스턴스

단일 가용 영역으로 낮출 수 있는 데이터를 세 개 이상에 두고 있다 다시 만들 수 있는 데이터는 S3 One Zone-IA로 내립니다 가용 영역이 손실되면 데이터도 손실됩니다. 원본이 따로 있어야 합니다

서버리스는 언제 싸고 언제 비싼가

"서버리스가 항상 싸다"는 서술은 틀립니다. 과금 축이 가동 시간에서 사용량으로 바뀔 뿐입니다. 사용량이 낮고 불규칙하면 유리하고, 높고 일정하면 불리해지는 구간이 생깁니다.

공식 문서 출처

  • AWS 백서 — AWS 요금이 작동하는 방식 — 과금 축의 구성과 서비스별 요금 요소
  • Amazon VPC 사용 설명서 — NAT 게이트웨이 — 가동 시간과 처리 데이터 두 축으로 과금되며 출발지·목적지와 무관하다는 서술
  • AWS PrivateLink 개념 — 게이트웨이 엔드포인트에 추가 요금이 없다는 점과 인터페이스 엔드포인트의 과금 축
  • Amazon EC2 API 레퍼런스 — StopInstances — 중지된 인스턴스에 사용 요금과 데이터 전송 요금이 부과되지 않지만 볼륨 요금은 계속된다는 서술
  • Amazon S3 사용 설명서 — 스토리지 클래스 사용 — 클래스별 최소 저장 기간과 검색 요금의 존재
  • Amazon S3 사용 설명서 — 수명 주기 전환 시 일반 고려 사항 — 30일 전환 제약과 128 KB 미만 객체 제외
  • Amazon S3 사용 설명서 — 멀티파트 업로드 개요 — 완료되지 않은 업로드가 저장 요금을 발생시킨다는 서술
  • Amazon S3 사용 설명서 — S3 버킷 키 — SSE-KMS의 KMS 호출 수를 줄이는 방법
  • AWS Savings Plans 사용 설명서 — 약정 대상이 시간당 사용 금액이라는 점과 유형별 적용 범위
  • Amazon EC2 사용 설명서 — 예약 인스턴스 — 약정 대상이 인스턴스 구성이라는 점과 영역 예약의 용량 확보
  • Amazon EC2 사용 설명서 — 스팟 인스턴스 — AWS가 용량을 회수할 수 있다는 성격
  • AWS 비용 관리 사용 설명서 — Cost Explorer — 비용 분석과 예측의 범위
  • AWS 비용 관리 사용 설명서 — AWS Budgets — 임계값 알림
  • AWS Cost and Usage Report 사용 설명서 — 가장 상세한 사용·비용 명세의 내보내기
  • AWS Compute Optimizer 사용 설명서 — 사용 지표 기반 라이트사이징 권고
