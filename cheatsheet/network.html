네트워크 연결 매트릭스

네트워크 문항의 첫 질문은 언제나 무엇과 무엇을 잇는가입니다. 연결 대상이 정해지면 후보가 서너 개로 줄고, 거기에 요구(전이 라우팅 · 인터넷 비경유 · 대역폭)를 얹으면 하나가 남습니다.

연결 옵션의 속성별 상세 대조는 헷갈리는 쌍 비교에 있습니다. 이 페이지는 어떤 상황에 어떤 옵션인가를 행렬로 고정합니다.

이 페이지 쓰는 법

  • 연결 매트릭스에서 행(연결 대상)을 먼저 고르고 열(요구)로 좁힙니다.
  • 트래픽이 안 통할 때는 막히는 지점 점검 순서를 위에서부터 따라갑니다.
  • 포트를 묻는 문항은 포트와 프로토콜에서 확인합니다.
  • DNS가 안 풀리는 시나리오는 DNS 동작 절의 두 속성부터 봅니다.
  • 배경 개념은 3장과 4장에 있습니다.

VPC 피어링은 전이 라우팅을 하지 않습니다. A와 B가 피어링되고 B와 C가 피어링되어 있어도 A는 C에 도달하지 못합니다. 연결 대상이 세 개를 넘어가면 조합이 급격히 늘어나므로 Transit Gateway가 답이 됩니다. 또한 CIDR이 겹치면 피어링 자체가 성립하지 않습니다.

Amazon Route 53 라우팅 정책과 식별 멤버
정책 무엇을 기준으로 응답하는가 식별 멤버 고르는 신호
단순(Simple) 레코드 하나를 그대로 응답합니다 없음 분기 조건이 전혀 없을 때

지연 시간 기반(Latency) 질의자에게 지연이 가장 낮은 리전으로 보냅니다 Region "가장 빠른 리전으로", 다중 리전 배포의 성능

다중값 응답(Multivalue answer) 여러 레코드를 무작위에 가깝게 응답하며 상태 확인을 연동합니다 MultiValueAnswer "로드 밸런서 없이 여러 대상에 분산"
IP 기반(IP-based) 질의자의 IP가 속한 CIDR 컬렉션으로 판단합니다 CidrRoutingConfig "특정 인터넷 서비스 제공자 사용자를 지정 경로로"

단순 라우팅을 제외한 모든 정책은 SetIdentifier가 필수입니다. 그리고 자주 나오는 혼동은 지연 시간 기반과 지리 위치입니다 — "가장 빠른" 이면 지연 시간 기반이고, "국가별로" 나 "규정상 특정 지역" 이면 지리 위치입니다. 한국어 자료 상당수가 지리 근접과 IP 기반을 빠뜨려 정책을 여섯 또는 일곱 가지로 서술합니다. 여덟 가지가 맞습니다.

포트와 프로토콜

아래 값 중 관계형 데이터베이스의 기본 포트는 Amazon RDS API 문서에서 확인한 값이고, GENEVE 6081은 Elastic Load Balancing API 문서에서 확인한 값입니다. 나머지는 프로토콜 표준 포트이며 AWS 고유의 설정이 아닙니다. 모두 구성에서 바꿀 수 있으므로, 문항이 명시적으로 다른 포트를 주면 그 값을 따릅니다. 여기 없는 서비스의 기본 포트는 1차 소스에서 확인하지 못해 싣지 않았습니다.

임시 포트 범위 32768-65535 VPC 사용 설명서의 예제 네트워크 ACL이 쓰는 범위. 실제 범위는 클라이언트 운영체제가 정합니다
네트워크 ACL 규칙 번호 1 ~ 32766 낮은 번호부터 평가합니다

막히는 지점 점검 순서

"연결이 안 된다" 유형의 시나리오는 아래 순서로 좁히면 거의 언제나 답이 나옵니다. 위에서부터 하나씩 확인하고, 처음으로 어긋나는 지점이 원인입니다.

연결 실패 시나리오의 점검 순서
순서 확인할 것 전형적인 증상
1 라우팅 테이블에 목적지로 향하는 경로가 있는가 프라이빗 서브넷에 NAT 경로가 없어 아웃바운드가 전부 실패
2 보안 그룹 인바운드가 허용하는가 포트나 출발지가 빠져 있어 특정 계층만 실패
3 네트워크 ACL의 양방향이 허용하는가 아웃바운드에 임시 포트 범위가 없어 요청은 가는데 응답이 안 옴
4 이름이 해석되는가 enableDnsSupport나 enableDnsHostnames가 꺼져 인터페이스 엔드포인트의 프라이빗 DNS가 동작하지 않음
5 CIDR이 겹치지 않는가 피어링이나 온프레미스 연결이 애초에 성립하지 않음
6 전이 라우팅을 기대하고 있지 않은가 피어링 두 개를 거쳐 도달하려다 실패
7 가용 영역 단위 구성 요소가 자기 가용 영역을 가리키는가 한 가용 영역의 NAT 게이트웨이가 죽자 다른 가용 영역까지 중단

3번이 이 목록에서 가장 많이 출제되는 지점입니다. 네트워크 ACL은 상태 비저장이므로 반환 트래픽을 규칙으로 명시해야 합니다. 보안 그룹만 보고 "규칙이 맞는데 왜 안 되지" 라고 판단하게 만드는 것이 문항의 설계입니다. 3장에 동작 원리가 있습니다.

공식 문서 출처

  • Amazon VPC 사용 설명서 — 라우팅 테이블 — 로컬 경로, 가장 구체적인 경로 우선, 대상의 종류
  • Amazon VPC 사용 설명서 — 보안 — 보안 그룹과 네트워크 ACL의 공식 비교표, 임시 포트 범위 예제, 규칙 번호
  • Amazon VPC 사용 설명서 — NAT 게이트웨이 — 가용 영역 단위 동작과 과금 축
  • Amazon VPC 사용 설명서 — VPC의 DNS 속성 — 리졸버 주소, enableDnsSupport와 enableDnsHostnames
  • Amazon VPC 피어링 안내서 — 기본 사항 — 전이 라우팅 불가와 CIDR 중복 제약
  • AWS Transit Gateway 안내서 — 허브 구조, 연결 유형, 라우팅 테이블
  • AWS PrivateLink 개념 — 엔드포인트 유형과 적용 범위, 엔드포인트 정책
  • AWS Site-to-Site VPN 사용 설명서 — IPsec 터널 구성과 가상 프라이빗 게이트웨이
  • AWS Direct Connect 사용 설명서 — 전용 회선의 성격과 가상 인터페이스
  • AWS Client VPN 관리자 안내서 — 개별 단말 연결과 인증 방식
  • Amazon Route 53 API 레퍼런스 — ResourceRecordSet — 라우팅 정책 여덟 가지의 식별 멤버와 SetIdentifier 요구 조건
  • Amazon Route 53 개발자 안내서 — Resolver — 인바운드와 아웃바운드 엔드포인트
  • Amazon RDS API 레퍼런스 — CreateDBInstance — 엔진별 기본 포트와 유효 범위 1150–65535
  • Elastic Load Balancing API 레퍼런스 — TargetGroup — GENEVE 프로토콜이 포트 6081을 쓴다는 서술
  • AWS Resource Access Manager 사용 설명서 — 서브넷 공유
